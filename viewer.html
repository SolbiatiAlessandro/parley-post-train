What the sidebar shows
  1. The game decides who acts next. For that one cog it writes a system message (the rules, the same every time except the cog's name) and a user message (standings, the full table history, this cog's secret FRIEND/ENEMY cards, the operator's strategy text, and the exact JSON it must reply with).
  2. The recorder on the Mac mini forwards both to Qwen3.5-4B on a Modal GPU. Qwen sees only that text: it has no memory between calls. Everything it "remembers" is in the history the game writes.
  3. Qwen writes one JSON object (the output). The game checks it, then applies it: the speech appears at the table on the left, and the shot is rolled. An invalid reply ends the whole game: there are no retries or substitute moves.
The table view on the left is public: no cards, no aim. The sidebar shows each cog's private prompt, so you see the secret cards too.
